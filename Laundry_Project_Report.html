Abstract

The Laundrymat / Dry Cleaning Order Tracking System is a robust, console-driven enterprise application developed in Core Java for small-to-medium laundry and dry cleaning businesses. In traditional laundry establishments, order management relies heavily on handwritten paper registers, manual paper receipts, and mental arithmetic. This outdated methodology frequently leads to misplaced garments, calculation errors, delayed deliveries, and financial discrepancies.

To resolve these operational bottlenecks, our team engineered an automated, menu-driven desktop system adhering strictly to Object-Oriented Programming (OOP) paradigms. The application provides comprehensive operational coverage: systematic customer registration, dynamic garment description, multi-tier service selection (Washing, Dry Cleaning, and Ironing), automated sequential order ID assignment, instant mathematical billing, 4-stage lifecycle status tracking (Received, Washing, Ready, Delivered), and financial settlement tracking (Pending vs. Paid).

Architecturally, the software demonstrates advanced Java concepts: encapsulation of private state, abstract base classes, runtime polymorphism, contract-based interfaces (Trackable), Java Collections (ArrayList, HashMap, TreeSet), defensive exception handling (InvalidOrderException), asynchronous multithreading for notification alerts, dual-stream file persistence (character streams and low-level byte streams), modern stream analytics via Java 8 Lambdas, and scaffolded JDBC SQL database methods.

Keywords: Core Java, Object-Oriented Programming (OOP), Laundry Management, File Handling, Multithreading, Java Collections, Java Streams, Software Engineering.

Chapter 1: Introduction

1.1 Background and Motivation

Laundry and dry cleaning services form an essential segment of daily urban commerce. In a typical dry cleaning facility, hundreds of garments move through diverse cleaning cycles every single day. Despite the high volume of daily transactions, a vast majority of small-to-medium dry cleaning businesses continue to manage operations using physical paper notebooks, carbon-copy receipts, and manual calculation. This operational model suffers from severe vulnerabilities: ink smudging in humid environments, misplaced clothing tags, billing arithmetic discrepancies, and lost customer histories.

The motivation behind this project is to develop an automated, lightweight, zero-dependency console application in Core Java that digitizes the entire lifecycle of a laundry order. By applying core computer science concepts—particularly Object-Oriented Programming (OOP), Java Collections, defensive Exception Handling, and File I/O—the system transforms manual, error-prone record-keeping into a predictable, transparent, and persistent software process.

1.2 Problem Statement

Traditional paper-based laundry management suffers from several critical bottlenecks:

  • Physical Record Degradation & Loss: Paper registers deteriorate rapidly in laundry environments exposed to steam, water, and cleaning solvents.
  • Garment Tracking Failures: When garments move between washing machines, chemical dry-cleaning tanks, and steam irons, workers frequently lose track of their current stage, resulting in lost clothes.
  • Manual Billing Discrepancies: Calculating per-garment service rates by hand during peak rush hours leads to calculation errors, undercharging customers or causing disputes.
  • Payment Disorganization: Tracking credit balances and knowing whether an order is Paid or Pending becomes chaotic across hundreds of open orders.

1.3 Project Objectives

The overarching objective is to build an automated, reliable, and user-friendly console application using standard Java. Specific technical objectives include:

  • Digital Customer Management: Store customer identity in encapsulated data structures.
  • Automated Sequential ID Generation: Issue unique sequential 4-digit identifiers starting from 1001.
  • Dynamic Pricing Engine: Compute totals automatically using OOP polymorphism based on service rates ($Quantity × Rate$).
  • Lifecycle Tracking: Monitor order progress across four standard stages (Received, Washing, Ready, Delivered).
  • Payment Settlement: Maintain transparent accounting records toggling orders between Pending and Paid.
  • Permanent File Persistence: Serialize records into flat text files (orders.txt) using character streams.
  • Automated Byte-Stream Backup: Duplicate data into orders_backup.txt using low-level byte streams.
  • Real-Time Stream Analytics: Use Java 8 Streams to generate business summaries displaying order counts, revenues, and top-value transactions.

Chapter 6: Implementation Details

6.1 Object-Oriented Principles in Source Code

The implementation adheres strictly to standard Object-Oriented Programming (OOP) paradigms:

1. Encapsulation: All critical attributes in Customer and Order are declared private and exposed only via public accessors:

static class Customer {
    private String name;
    private String phone;
    Customer(String name, String phone) { this.name = name; this.phone = phone; }
    String getName() { return name; }
    String getPhone() { return phone; }
}

2. Inheritance & Abstraction: An abstract base class LaundryService defines the contract, while subclasses provide concrete implementations:

static abstract class LaundryService {
    abstract String getName();
    abstract double getRate();
}
static class WashingService extends LaundryService {
    String getName() { return "Washing"; }
    double getRate() { return 50.0; }
}

3. Polymorphism: An array of parent references LaundryService[] enables dynamic method dispatch at runtime:

LaundryService selectedService = serviceOptions[serviceChoice - 1];
double amount = selectedService.getRate() * quantity;

4. Interfaces: The Trackable interface formalizes status update capabilities:

interface Trackable { void updateStatus(String newStatus); }
